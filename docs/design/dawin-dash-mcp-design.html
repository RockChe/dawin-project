2. 查證

項目結果
現成的 REST APIdocs/api-spec.md 寫的 /api/mcp/* 與 MCP_API_KEY 只有規格、沒有實作（程式與歷史都查過）；chatbot/ 只有文件。要從頭做。
現成輪子Vercel mcp-handler：把 MCP 伺服器掛進 Next.js 路由、有 withMcpAuth。Apache-2.0、近半年有發版（v2.2.0）。682★ 未達 1k 門檻（領域冷門，放寬並明講）。
版本風險2.x 需 MCP SDK 第 2 版＋zod 4＋Node 20（你們 Node 22）。SDK v2 已於 2026-07-27 成為穩定版（官方 main 分支，2026-10-07 查證）；採用 v2，不保留 1.x 備案（1.x 只剩約半年維護期）。原稿「穩定度未確認」是舊索引資料，已更正。
可重用的既有資產權限矩陣（read／write／manage／self）、稽核紀錄、關注人與執行人推導規則、已有的後端動作與測試。
主要缺口後端動作全綁「登入 cookie 的人」，MCP 沒有登入畫面；動作核心要抽成「給定身分即可執行」才能共用。

5. 金鑰與身分

項目做法
誰發金鑰每個人在設定頁自助建立、可撤銷；金鑰只在建立時顯示一次
綁定金鑰綁建立者的帳號，角色跟著帳號（viewer 的金鑰只能讀）；建立時可再縮成「唯讀」
儲存只存雜湊（SHA-256；金鑰是 32 位元組隨機值，不需要慢雜湊）與前綴；格式 dd_live_…
資料表api_keys(id, user_id, name, key_prefix, key_hash 唯一, scope 讀/寫, created_at, last_used_at, expires_at, revoked_at)
帳號被刪或降權金鑰隨帳號失效（外鍵連鎖刪除、每次驗證都重讀目前角色）

6. 稽核與限速

每次工具呼叫記一筆稽核：動作名 MCP_工具名、哪個人、哪把金鑰、參數摘要。限速以資料庫計數（每把金鑰每分鐘次數），因為無伺服器的記憶體限速只對單一實例有效。

7. 刪除：先不開放（已決定）

原因：專案目前的刪除是永久的（沒有垃圾桶，只有每天凌晨 4 點的備份可還原）；而畫面上的「Archive」只是暫時隱藏、沒有存進資料庫（重新整理就消失）。所以 MCP 第一版完全沒有刪除工具。
寫入的保護：稽核（誰、哪把金鑰、做了什麼）、每把金鑰限速、viewer 金鑰唯讀。Claude 客戶端本來就會在每次工具呼叫前請你核准，所以不另加「預覽再確認」。
之後若要：先把「封存」做成真的功能（資料庫欄位＋畫面），MCP 再提供封存工具取代刪除。這是另一項工作，不在本計畫內。

8. 重構範圍（讓網頁與 MCP 共用）

把 server/actions/tasks.js 與 projects.js 裡 create／update／delete／toggle 的核心抽到 server/domain/，函式簽名為 (actor, args)；網頁動作改成「withCap 驗登入 → 呼叫 domain」，MCP 工具改成「驗金鑰 → 呼叫 domain」。既有 800+ 個測試保護行為不變；每抽一支就跑一次全套測試。

#發現查證處置
P1每個工具要有唯一的「工具→權限」登記表；實際檢查 = 帳號權限 ∩ 金鑰範圍 ∩ 工具允許；未知工具預設拒絕；domain 模組要 server-only，避免變成可被客戶端呼叫的 Server Action合理（本專案權限矩陣即此模式）採納：新增 MCP 工具矩陣並納入 authzCoverage 測試
P1withMcpAuth 的 required 預設 false，驗證失敗會放行已查證（官方原始碼 required = false）採納：一律 required:true，並測無金鑰、無效金鑰、只有 cookie 皆被擋
P1抽 domain 時必須保留完整 db.batch 邊界；owner 重算要有並行鎖策略（先鎖父任務再改）；要有真實 Postgres 並行測試合理；既有 batch 是原子的，並行重算是新增風險採納：先整段 batch 搬移、不拆開；加並行測試。團隊規模小，列入第 1 期驗收
P1業務寫入與稽核必須同一 batch 提交；稽核含 user、key、request_id、目標與前後值；不存原始金鑰合理採納
