5. 現有資料怎麼轉（取代對照表要逐筆決定）

情況做法

任務負責人和子任務完全一致關注人留空，不用動
疑似髒資料（例如子任務負責人寫成「車」）仍需你手動改那個子任務，這種我不自動猜

6. 上線順序（資料庫要動，要你點頭）

① 先在正式資料庫新增一個欄位（只新增、可為空，舊程式不受影響）→ ② 轉換現有資料（先預覽、你看過再套用）→ ③ 才部署新版程式。順序反了新版會讀不到欄位。我只準備好腳本，不會自己對正式庫動手。

7. 不做什麼

不做「專案層級」負責人；不做權限控管（誰能改誰的關注人）；不改 API 與 chatbot 讀取的 owner 欄位格式。
