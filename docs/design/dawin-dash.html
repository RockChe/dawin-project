  1. 需求一 — Overview 時間線 TODAY 線畫錯位置。 系統日期 2026-09-04，虛線卻落在 6／7 月交界。 不是「線不會動」：todayPct 每次 render 都用 new Date() 重算，數值正確； 錯的是它被當成可視容器寬度的百分比，而月份格線用的是 ovMinW 軌道寬度—— 圖一橫向捲動，兩個基準就分家。
  2. 需求二 — Projects 專案詳情頁的 Tasks 列表要能排序與篩選。 維度：狀態、日期、負責人、緊急度。設定要 per-user 持久化（「存到個人自定義的紀錄」）。
  3. 需求二的四項裁決（各附一份問答圖檔，見第 10 章）：
    · 記憶範圍＝全域一組（非每專案一組）

    · 單一排序（非多重）＋ 三個篩選欄位全部多選

2 技術棧

層選型版本 為什麼是它被否決的替代方案
前端框架Next.js App Router + React15.3 / 19 Server Actions 直接打 DB，省掉一層 REST；Vercel 零設定部署 Vite SPA：得自己搭 API 層與 auth 中介
資料層（full-stack）Neon PostgreSQL + Drizzle ORM0.39 Serverless PG 冷啟快、有真交易與外鍵；Drizzle schema 即型別 Prisma：engine binary 在 Vercel 上肥；raw SQL：schema 漂移無從察覺
資料層（gws）Google Sheets API v4 + 自建 DALv4 小團隊要能直接開試算表看／改資料，零 DB 維運 Airtable：授權與配額成本；直接用 PG：非工程使用者進不去
檔案儲存Cloudflare R2（full-stack）／ Google Drive（gws）S3 相容 / v3 R2 無 egress 費；gws 版沿用團隊既有的 Drive 權限模型 S3：egress 計費；存 DB：blob 撐爆備份
個人化設定user_settings 表 + useUserSettings— 已在跑：zoom／projectsView／hiddenProjects／timelineSort 都是這套，本次新增的 projectTaskView 沿用同一個模式 localStorage：換裝置就沒了、進不了備份
新開一張表：一個 key-value 需求不值得
認證自建 session（bcryptjs + cookie）— 內部工具、單一 tenant，不需要 OAuth 那層複雜度 NextAuth：設定面大於需求；JWT 無狀態：撤銷 session 做不到
時間線繪製手刻 absolute % 定位（無圖表庫）— 甘特列要同時掛拖曳、hover、進度覆蓋層，庫的封裝反而礙事 frappe-gantt / vis-timeline：客製深度不夠
代價：定位基準得自己顧——需求一的 bug 正是踩在這裡
排序／篩選純函式 + Array.sort（穩定）— 18 筆規模，前端算完即可；穩定排序讓「同組維持 sortOrder」是免費的 後端排序：多一次往返換不到東西
多重排序：第二層已由 sortOrder 接住，見問答檔
Bot（chatbot）FastAPI + Claude API tool usePy 3.12 意圖理解交給模型，bot 只維護 tool schema 規則式指令解析：中文自由輸入撐不住

本文件圖表手刻 inline SVG— file:// 直開即圖、零 JS、無暗色分支 mermaid：2026-08-27 已於 cc_skill 廢除
