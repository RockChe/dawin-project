Tasks 排序／篩選 —— 設定記憶範圍三選一

2026-09-04 · 供 Rock 裁決 · 未經 confer（釐清規格，非方案取捨）

問題來源（Rock 原話）

我希望這邊，可以按 狀態 排列 篩選 來討論下 可以按 狀態 排列 篩選，或是按 日期、負責人、緊急度 然後這部分的設定 是可以存到 個人自定義的紀錄

「存到個人自定義的紀錄」＝ per-user 持久化，已確定。未定的是：一組設定跨所有專案共用，還是每個專案各記一組。

三個選項的差別：切換專案時會發生什麼

一句話比較

選項使用者感受儲存什麼時候會後悔
A 全域一組 換專案，篩選跟著你走 user_settings 1 筆 當你有一個專案想長期只看「待辦」、另一個想看全部時，每次切換都要重設
B 每專案一組 每個專案記得自己的樣子 每專案 1 筆，隨專案數成長 當你其實每個專案都用同一種看法時，等於每個專案都要手動設一次
C 兩層 預設跟著走，特定專案可釘住 1 筆全域 + 覆寫若干筆 當你忘記某專案被釘過，看到的畫面跟預期不同卻找不到原因
我的建議：A。 理由不是「A 比較好」，是現在還不知道你會不會需要 B——A 的資料形狀是 C 的子集， 之後要升級成 C 只是多讀一層 key，既有的全域那筆原封不動。 反過來先做 B 或 C，就得先養一套清理與落回邏輯，而那套邏輯可能永遠用不上。

既有前例：timelineSort、projectsView、hiddenProjects 都是全域一組（A 形狀）， 照 A 走的話這個功能跟它們是同一個模式，不會多出第二種心智模型。
